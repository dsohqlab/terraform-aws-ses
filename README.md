# terraform-aws-ses

Terraform module to manage AWS **Simple Email Service (SES / SESv2)** - transactional, bulk, and inbound email - one composite spanning the modern SESv2 API (identities, configuration sets, event destinations, contact lists, dedicated IPs, tenants, account-level suppression/VDM) and classic SES (DKIM/verification plumbing, MAIL FROM, receipt-rule inbound processing, templates), because SESv2 has no inbound-mail equivalent yet.

---

## Overview

- Provisions **SESv2 domain and mailbox identities** with Easy DKIM or bring-your-own-DKIM signing
- Manages **custom MAIL FROM domains** for DMARC-aligned bounces on both SESv2 and classic APIs
- Builds **configuration sets** with TLS-required delivery, reputation tracking, and account-wide suppression baked in
- Wires **event destinations** (SNS, CloudWatch, EventBridge, Kinesis Firehose, Pinpoint) for bounce/complaint/delivery telemetry
- Manages **contact lists** with topic-level subscription preferences for bulk/marketing sends
- Manages **dedicated IP pools** and assignment of already-provisioned IPs
- Enables **account-wide suppression** of bounced/complained addresses by default (secure baseline)
- Supports **multi-tenant sending isolation** via SESv2 tenants
- Builds the **classic-SES inbound pipeline** - receipt rule sets, ordered rules with S3/Lambda/SNS/bounce/stop/WorkMail actions, account-level IP filters, and the single active-rule-set designation
- Manages classic **send templates**

## AWS Prerequisites

- **New accounts start in the SES sandbox** - sending is capped (typically 200/day) and restricted to verified recipients until an AWS Support case grants production access. This is an AWS Support action, not something Terraform manages.
- **Domain/email verification requires DNS records this module does not create** - wire this module's `dkim_tokens` / `verification_token` outputs into `record` resources via `terraform-aws-route53`.
- **Easy DKIM CNAME targets can vary by identity and Region** - get `DkimAttributes.SigningHostedZone` from SES when constructing records; the module outputs tokens but not that hosted zone.
- **`aws_ses_domain_identity_verification` blocks `apply`** for up to 45 minutes polling DNS. Set `classic_domain_identities[*].verify = false` for a first apply before the DNS record exists.
- **Mailbox identity verification cannot be completed by Terraform** - a human must click the emailed verification link.
- **MAIL FROM domains require a caller-managed MX record** (`10 feedback-smtp.<region>.amazonses.com`).
- **Only one receipt rule set can be ACTIVE per account/Region** - coordinate `active_receipt_rule_set_key` across every caller in the same account/Region.
- **No region constraint** - SES/SESv2 is a regional service with no us-east-1 global-resource requirement (unlike CloudFront/WAFv2/ACM).
- **Quotas:** 10,000 verified identities per account (soft); 40 receipt rules per rule set (soft); 50 receipt rule sets per account (soft).

## Quick Start

```hcl
module "ses" {
  source = "dsohqlab/ses/aws"
  version = "1.0.0"

  domain_identities = {
    main = {
      email_identity = "example.com"
    }
  }

  mail_from_domains = {
    main = {
      email_identity_key = "main"
      mail_from_domain   = "bounce.example.com"
    }
  }

  configuration_sets = {
    transactional = {
      configuration_set_name = "transactional"
    }
  }

  tags = {
    Environment = "prod"
    Application = "notices"
  }
}

# Wire the DKIM + verification tokens into Route 53 (owned by the caller):
module "route53_ses_records" {
  source = "terraform-aws-modules/route53/aws"
  version = "6.5.1"

  #...
  # records built from module.ses.domain_identities["main"].dkim_tokens
}
```

## Troubleshooting

- **`terraform apply` hangs for ~45 minutes then fails on `aws_ses_domain_identity_verification`** - the `_amazonses` TXT record is missing or hasn't propagated. Set `verify = false` on that `classic_domain_identities` entry, apply, create the Route 53 TXT record from the `verification_token` output, then flip `verify = true` back on and re-apply.
- **`KMS.AccessDeniedException` or S3 `AccessDenied` on inbound mail** - the CMK key policy and/or the S3 bucket policy must separately grant `ses.amazonaws.com` `kms:GenerateDataKey`/`s3:PutObject`; this module does not manage those policies (see SCOPE.md Out-of-scope resources).
  Mixing SESv2's `USE_DEFAULT_VALUE`/`REJECT_MESSAGE` casing with classic SES's `UseDefaultValue`/`RejectMessage` on the wrong variable will also fail at the AWS API - not at `terraform validate`.
- **Tag drift / tags never appear on most SES resources** - only `aws_sesv2_email_identity`, `aws_sesv2_configuration_set`, `aws_sesv2_contact_list`, `aws_sesv2_dedicated_ip_pool`, and `aws_sesv2_tenant` support `tags` in the AWS provider schema; every classic-SES resource and several SESv2 sub-resources have none. This is expected - not a bug.
- **Credential-chain failures (`NoCredentialProviders`, `ExpiredToken`)** - confirm `AWS_PROFILE` / SSO session / OIDC role assumption at the root/provider level; this module never accepts credential variables.
- **Emails stuck in the SES sandbox** - new accounts can only send to verified addresses at a low daily quota; request production access via an AWS Support case.
- **Second `terraform-aws-ses` caller silently deactivates the first module's active rule set** - only one receipt rule set can be ACTIVE per account/Region; coordinate `active_receipt_rule_set_key` ownership.
- **Mailbox identity stuck `PENDING` forever** - `email_identities` / `classic_email_identities` require a human to click an emailed verification link; Terraform cannot complete this step.
